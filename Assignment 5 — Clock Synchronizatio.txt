What is Clock Synchronization?

In distributed systems:

Each computer/node has its own clock.
Due to hardware differences, clocks may show different times.

This causes problems in:

Banking systems
Distributed databases
Online transactions

So clocks must be synchronized.

What is Berkeley Algorithm?

The Berkeley Algorithm is a clock synchronization algorithm where:

One node acts as Master
Other nodes act as Slave nodes
Master collects all times
Computes average time
Sends adjustment values to all nodes
Real-Life Example

Suppose:

Node	Time
Node 0	10
Node 1	12
Node 2	14

Average:

(10 + 12 + 14) / 3 = 12

Adjusted Times:

Node 0 → +2
Node 1 → 0
Node 2 → -2

Final synchronized time:

12
Berkeley Algorithm Architecture
            Master Node
                 |
     -------------------------
     |           |           |
   Node1       Node2       Node3

1. Master collects times
2. Calculates average
3. Sends adjustments
4. All clocks synchronized

Working of Berkeley Algorithm
1. Select Master Node
2. Master requests time from all nodes
3. Collects all clock values
4. Computes average time
5. Sends adjustment values
6. Nodes update clocks
Advantages
Simple synchronization method
Useful in distributed systems
No external UTC clock required
Disadvantages
If master fails → synchronization fails
Delay in communication affects accuracy
Difference Between Berkeley and Cristian Algorithm
Berkeley Algorithm	Cristian Algorithm
Uses average time	Uses time server
Internal synchronization	External synchronization
Master computes average	Client adjusts to server
